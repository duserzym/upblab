# UX conventions in the shell

Rules 1–7 are written once, in grainatlas:
[`docs/ux-conventions.md`](../../grainatlas/docs/ux-conventions.md) (the
source; read it there). This page says where UPb Lab's shell follows
each one, and which do not apply to it. Rule 8 sets the shell's layering
contract. Module tabs follow the rules in their
own code; the shell's part is to pass them what they need (theme, files,
sign-in) and to give them the whole area under the tab bar.

| Rule | In the shell |
| --- | --- |
| 1. System by default, with light and dark | Settings → Appearance and layout offers System, Light, Dark; nothing explicitly chosen means System (`ui/src/lib/settings.svelte.ts`). System follows the operating system, including live changes. The resolved `light` or `dark` is always written on the shell's `<html data-theme>`. Choices stay in the viewer's settings (`settings.json` on desktop, `localStorage` on the web), never on a server. Older saved defaults migrate to System unless `themeChosen` is true. Every tab changes at once without reloading: modules receive the resolved theme through bridge v3.1, a host-written `data-theme` attribute where accessible, and `?theme=light\|dark` at load. See [bridge-theme.md](bridge-theme.md). |
| 2. One gesture module for image views | Does not apply: the shell shows no image. Images are grainatlas's, inside its tab. |
| 3. One click for a good result, Auto, Reset | Does not apply: the shell has no processing controls. |
| 4. Open anything, never ask what it is | A folder or files dropped anywhere on the window (tab bar, Home, either module tab), opened from the Finder or Explorer, or picked with Home's **Open folder…** / **Open files…** go to the tab that reads them, decided by content (`ui/src/lib/drop.ts`, rules at the top): packages, area folders, images and `.grainatlas` projects to Images; Qtegra export folders, zips and CSVs to Sessions (`laicpmsdb://ingest?path=` on the desktop). The files reach the module through `@lab/bridge` `open-files` (protocol v2, `bridge/README.md`); the host lists and reads them (`src-tauri/src/files.rs`), the module never sees a host path it was not given. A `.zag` file stands for its package folder. Nothing the modules cannot read is refused with a line saying what can be opened. File associations: `docs/installing.md`. Home's four action tiles are **Open folder**, **Open files**, **Upload LA-ICP-MS session** and **Upload image set**; an upload tile starts the upload in one click and its card shows handoff progress and Review links; each refuses files for the other module. |
| 5. The scale is known, or asked once | Does not apply to the shell: the scale is grainatlas's question, asked after the files arrive through `open-files`. |
| 6. Server features are additive and say where data comes from | One server setting (Settings → laicpmsdb: a lab server or "This computer"); the tab bar names the server in the sign-in button's tooltip and dialog; the sign-in is the shell's (`token()` for modules), kept in the OS keychain, never in a URL or file. Home says which part is missing (no server, unreachable, signed out) next to the list it affects. |
| 7. Fit a 14-inch laptop | Checked at 1440 × 900 and 1280 × 800 CSS pixels, and Home and Settings at 1024 × 640, in Chromium and WebKit: first-run wizard, Home (also while files are dragged over it), Images, Sessions, Review (including plots and details), Reduce, Settings, sign-in dialog; module tabs get the full width and all the height under the 48 px tab bar (`ui/tests/sizes.spec.ts`, `ui/tests/review.spec.ts`, `make e2e`, part of `make test`). Long URLs, paths and ids wrap; pages scroll inside the window, never sideways. The window opens at 1280 × 800 centred, cannot go below 1024 × 640, and reopens where it was left, fitted to the monitor it is on (`src-tauri/src/geometry.rs`, `window.json` in the app config folder). Settings → Appearance and layout → **Reset layout** returns it to 1280 × 800 centred. Review remembers its scope and the Side by side choice; the split with the existing Images surface adapts down to the smallest supported window. Review tiles enforce minimum sizes and collapse metadata, then Spots, into header rails when needed (SEM yields next if a vertical stack still cannot fit); a rail temporarily maximises its tile. Balanced resets the current mode’s layout; Plots focus and Image focus offer alternate arrangements, with split and solo layouts stored separately. Tile maximise lasts only for the app session. Each Review column scrolls within the window. Home's card grids show 4 cards across at 1440 px, 3 at 1280 and 2 below 1100 (`ui/tests/home.spec.ts`); the Review geochemistry board shows 3 x 2 panels when its own width is 880 px or more, else 2 x 2, and scrolls vertically for more (`ui/tests/review.spec.ts`). Theme: every tab is checked in light and dark (`ui/tests/theme.spec.ts`). |
| 8. Layers stay within their owner | L0 tiles are dock panels in flow. L1 in-tile drawers are pickers kept open while looking at the result: depth channels, geochemistry axis quantities, session and run pickers. They open inside their own tile or toolbar and take layout space; content beside or below shrinks. They never float. L2 anchored menus are short, one-shot choices (move panel, presets, row actions). They may float, using the shared `containedPopover` / `containRect` helper to stay inside the owning tile, flip above or right-align to the anchor near an edge, and clamp every edge. They never extend over another tile or a module surface; a menu for a native surface takes layout space above it. L3 app dialogs and popups outside a tile use the shared overlay registry (`ui/src/lib/overlays.svelte.ts`): every visible module surface is hidden and replaced by a quiet placeholder of the same size before opening, then restored on close. Future toasts use a reserved strip of shell chrome that no module surface covers. Nothing relies on z-index to paint over a native module surface. |

## What the modules still adopt

- **grainatlas**: register `onOpenFiles` when hosted and pass the set to its
  Open screen code; in the desktop shell every drop on the window arrives
  that way (`bridge/README.md`, grainatlas section).
- **laicpmsdb**: the `#/ingest` route (with `?path=`; today the ingest dialog
  lives on the timeline and laicpmsdb has no such route) and `onOpenFiles`
  there, feeding the ingest dialog (`bridge/README.md`, laicpmsdb section).
  It already reads `?theme=` (laicpmsdb 25c69fd).
